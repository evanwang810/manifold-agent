01

Calibration, not profit

Profit is a bad success metric for an LLM trading agent, and chasing it will teach you nothing. Once a few hundred people run GPT-class agents on the same markets, the LLM consensus is the price. You are not trading against uninformed humans. You are trading against a distributed version of yourself, with a similar training cutoff and access to the same search results.

Fees and spread eat most of what is left. If your true edge is three points and the spread is two cents wide, you are playing for one point on capital locked up until resolution. The modest returns people report are not underperformance. They are roughly what the arithmetic allows.

So this agent optimizes for something measurable instead. Every decision appends one line to events.jsonl recording the model's probability beside the market's, at the moment it decided. After a few hundred resolutions that file is a reliability diagram.

The interesting output is a sentence like "well calibrated on sports, systematically overconfident on geopolitics." That is real information about a specific agent architecture, and unlike alpha, nobody can arbitrage it away.

02

One tick, four stages

There is no daemon and no state held in memory. A run wakes up, reads its state from a git branch, does the most urgent single thing it can afford, writes state back, and exits. Priority is fixed and descending: react to what already happened before going looking for something new.

03

Evidence before the number

An evaluation is two calls. First a grounded research pass with live search, which reports the state of play with dates and is explicitly forbidden from stating a probability. Then a structured decision that sees the market, the full comment thread, the research, and the agent's own memory.

The decision schema is ordered deliberately. The model must write out evidence for, evidence against, its key uncertainty, and the ways the market could resolve against its plain reading, before it is allowed to emit a number.

This is not decoration. Left to themselves, small models pile every answer onto 0.7 and 0.3. Forcing the reasoning to land first measurably widens the distribution, and a flattened distribution destroys the entire calibration signal.

// propertyOrdering is load-bearing
{
  evidence_for:      string[],
  evidence_against:  string[],
  key_uncertainty:   string,
  resolution_risk:   string,
  probability:       number,
  confidence:        "low"|"medium"|"high",
  action:  "buy_yes"|"buy_no"|"sell"|"hold",
  comment:           string,
  memory_note:       string
}

The system prompt tells it the market price is a strong prior, that disagreeing requires a reason it can name, that resolution criteria should be read literally because many questions resolve on a technicality, and that hold is a good answer most of the time.

04

The part that stops it blowing up

The default trade is M$10. Size grows only when every conviction gate passes at once. Miss any one of them and it is back to a nibble.

Sizing waterfall

Quarter-Kelly on stated edgeM$500
× time decay, 14 / days_leftM$350
cap at 5% of lifetime volumeM$200
daily budget, balance reserveM$150
price impact under 3ptM$90
order sentM$90

Time decay exists because mana locked in a market resolving three weeks out is mana you cannot use. Far-dated conviction is still conviction, but it is a worse trade than the same conviction resolving Friday.

Impact is measured, not modelled

Manifold's bet endpoint takes a dryRun flag and returns the probability the order would leave behind, without executing. The agent places a fake order, reads the resulting price, and shrinks until impact is under three points.

This matters more than it sounds. Manifold's order books are thin enough that a large order mostly trades against itself: you move the price to where you no longer believe it, then own the position at your own worse price. Measuring it beats reimplementing their AMM and hoping the two stay in sync.

Resting, not crossing

Non-conviction trades go in as limit orders priced to keep 60% of the estimated edge, expiring in 24 hours. A market that runs away before filling simply does not fill, which is the correct outcome and costs nothing.

05

Run your own

Roughly ten minutes. You need a Manifold account and one LLM key. Everything runs on GitHub's free tier, which is unlimited for public repositories.

  1. Fork the repository

    Keep it public. Actions minutes are unlimited on public repos, and a 5-minute cron would burn a private repo's 2000 monthly minutes in about three days.

    gh repo fork evanwang810/manifold-agent --clone

  2. Make the bot an account

    Use a fresh Manifold account rather than your own, so its P&L and its comments stay separate from yours. Open Edit profile, scroll to the API key field, generate one. That key is the account: anyone holding it can spend the mana and post as it.

  3. Get an LLM key

    Gemini is the default. Its native search grounding means research needs no second API key, and retrieval matters more than raw model strength here. A mid model with three good articles beats a strong model working from a training cutoff. Mistral and any OpenAI-compatible endpoint work too, with one config line.

  4. Create the state branch

    The agent stores its memory on an orphan branch of its own repository. Committing there on every tick also keeps the schedule alive, since GitHub disables cron workflows after 60 days of repository inactivity.

    git switch --orphan state
git commit --allow-empty -m "init state"
git push -u origin state
git switch main

  5. Add the two secrets

    Settings → Secrets and variables → Actions. Or from the terminal, which will prompt you to paste each value.

    gh secret set MANIFOLD_API_KEY
gh secret set LLM_API_KEY

  6. Set your handle

    In config.toml, set owner_username to your handle, not the bot's. That is how it recognizes you in comment threads and answers you first.

  7. Watch it think before it spends

    Dry run is the default. Bets go through the dryRun flag and comments are logged instead of posted, so a full tick runs end to end without touching anything. Read events.jsonl on the state branch and judge the reasoning yourself.

    pip install -e . && python run.py

  8. Go live

    Set dry_run = false in config.toml and commit. The cron is already running: it fires every five minutes and skips cleanly until the secrets exist. Each run posts a summary to its Actions page.

On the schedule. GitHub treats cron as best effort and delays or drops runs under load, so the real cadence is closer to 5 to 15 minutes. Every tick is independent and reads its state fresh, so this changes nothing except how often the agent gets to think.
06

Telling it what to do

Three channels, in increasing order of permanence.

ChannelLifespanUse it for
workflow inputone runType into the instruction box when triggering a run by hand. Useful for "skip the scan today" or "there is breaking news on market X."
Manifold replythe conversationReply to any of its last ten comments. Messages from the configured owner are answered first and labelled as such, so it knows the difference between you and a stranger.
instructions.mdforeverEverything below the horizontal rule is injected into the system prompt on every tick. This is where behavior changes belong: category bans, confidence caps, resolution-criteria standards.
Instructions change how it thinks, never how much it stakes. Sizing is computed in code after the model has spoken, so nothing written in a prompt, by you or by anyone commenting on a market, can talk it into a larger position than the risk config allows.
07

What it does not do

  • Binary YES/NO markets only. Multiple choice, numeric, and other contract types are skipped rather than handled badly.
  • It cannot see mentions everywhere. Manifold has no public notifications endpoint, so replies are only found under the bot's own last ten comments.
  • Managram replies are off by default. A managram is the only way to answer a managram, and the API minimum is M$10, so every reply costs real bankroll.
  • Nothing exits on a schedule. Positions close when a re-evaluation returns sell, or when the market resolves on its own.
  • It is play money. This is a calibration experiment with a scoreboard attached, not a trading strategy, and it is not investment advice.
